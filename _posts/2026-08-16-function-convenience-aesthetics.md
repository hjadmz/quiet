title: Function → Convenience → Aesthetics
description: My design philosophy, inspired by Dieter Rams.
toc: true
---

I keep coming back to the same hierarchy when I design something:

**Function → Convenience → Aesthetics.**

Not because aesthetics are unimportant. They matter a lot. But they work best when they are built on top of something that already has a reason to exist.

## Function

First: does it actually work?

A product should solve the problem it claims to solve. An interface should communicate what it does. A feature should justify the complexity it introduces.

If the foundation is wrong, polishing it doesn't make the product better.

## Convenience

Once something works, the next question is how much friction remains.

Can a step disappear? Can the interface explain itself without instructions? Can the common action become faster without making everything else harder?

Convenience is where a functional object starts becoming a good product.

It is also where restraint matters. Adding another button, setting, integration, or automation can make something technically more capable while making the overall system worse.

## Aesthetics

Then comes aesthetics.

Aesthetics aren't a coat of paint applied at the end. Typography, spacing, motion, materials, sound, and visual hierarchy affect how a product is understood and how it feels to use.

But beauty has more value when it reinforces function instead of competing with it.

The goal isn't minimalism for its own sake. It isn't maximum functionality either.

It's enough.

Enough capability to solve the problem. Enough convenience to make using it natural. Enough aesthetic intention to make the experience feel considered.

That's the standard I want to use for the things I build.

And that's largely what this site is for: documenting those things as I learn how to build them better.

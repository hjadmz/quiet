{%- comment -%} An interactive demo, inlined into the page at build time. Usage, one line in a post: {% include demo.html src="demos/hue-mixer.html" title="Hue mixer" height="220" caption="Drag to change the swatch." %} The demo itself is an ordinary HTML file under _includes/demos/ — a whole document, with its own CSS and script, that the author can open in a browser and work on normally. Nothing about it is special until it is included. Why srcdoc rather than a file the browser fetches: - It is inlined at build time, so the page makes no extra request and the "no third-party runtime" promise holds by construction rather than by policy. - `sandbox="allow-scripts"` without `allow-same-origin` gives the frame an opaque origin: its scripts cannot read this page, its cookies, or its storage, and nothing it does can reach the site around it. - Files under _includes/ never become URLs, so a demo cannot be crawled, linked, or mistaken for a page. With JavaScript off the frame still renders the demo's static initial state, and the caption still says what it would have done — so write the demo so its starting state means something, the same discipline alt text asks for. Two things a demo cannot do, both by design: reach storage or cookies (the opaque origin denies them, and the attempt throws), and navigate the page around it. If a demo needs to remember something, keep it in a variable. It also cannot see the site's theme toggle, so it follows the reader's system setting instead. Give the demo `color-scheme: light dark` and it reads well either way. `height` is fixed, because an iframe cannot size itself to its content without script on both sides. Give it headroom: if a reader has raised their default text size the content grows, and a frame with slack absorbs that instead of scrolling inside itself.
